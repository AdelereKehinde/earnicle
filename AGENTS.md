# Earnicle — Agent Context

## What this app is
Earnicle is a read-to-earn / write-to-earn content platform.
- Readers earn small amounts ($0.15–$0.20) per article read to completion, can unlock
  premium articles, and can join a writer's Pro membership.
- Writers earn from views, paywall unlocks, and memberships, and can withdraw
  earnings to a bank account via Paystack.
- "Story" = long-form article. "Short" = short-form text post (NOT video).
  Both are created from one editor screen with a Stories/Shorts toggle —
  do not build separate editors unless explicitly asked.

## Stack
- React Native (Expo), TypeScript
- Backend: FastAPI (separate service; consumed over REST)
- Cloudinary: avatar and cover image hosting (client uploads via unsigned preset)
- Paystack: payments/withdrawals (test mode keys currently)

## Screens (25 total)
Onboarding/splash (4) → Choose your path → Auth (sign up, sign in, verify email,
forgot/reset password, password changed) → Home feed → Explore (Stories/Short
toggle, categories, trending, writers to follow) → Earnings (simple + detailed

## Database (FastAPI backend)
The backend is now a separately-built FastAPI service exposing a REST API.
The schema and SQL migrations may be kept in `reference-only/supabase/` for
documentation, but all data access and business logic live in the FastAPI
service. The frontend must call the REST endpoints; do not add server or
database code to this repository.

## Security rules — non-negotiable
- Never put any secret key in `EXPO_PUBLIC_*` env vars. Only public client keys
  (Cloudinary unsigned preset, Paystack public `pk_...`) may be exposed to the
  client.
- Secret keys (Paystack secret, database credentials, service tokens) live in
  the backend environment or a secrets manager. Do not store them in this
  repository or in any client-side env.
- All sensitive server-side operations (payments, payment verification,
  withdrawals) must be implemented on the FastAPI server. The frontend calls
  the server's REST endpoints — never call third-party secret-key endpoints
  directly from client code.
- Never read, print, or include the contents of `.env` in any output.
- Keep `.env` and any real secret files out of version control (`.env` should
  remain in `.gitignore`). Use `.env.example` to document required variables.

## Money & numbers
- All monetary columns are `DECIMAL(10,2)` — always format to 2 decimals in the UI
- Round every displayed number; never show raw floating-point output

## Workflow / branching
- `frontend` branch = screens and RN app code (Codex's lane — it takes image
  input directly from Figma exports or provided mockups)
- `backend` branch = FastAPI server code, schema migrations, and any server-side
  business logic (OpenCode/DeepSeek's lane — text-only, no images)
- Merge both into `main` daily; do not run both agents on `main` concurrently
- Do not touch the other lane's primary directory without asking:
  - `frontend` owns `/app/(screens)` and `/components`
  - `backend` owns server and migration files (kept in the backend repo)
  - Shared contract: `/lib/api.ts` (client init) and `types.ts` (generated by
    the backend team) — coordinate with backend when the schema changes.

## Persistent auth session (no flicker on launch)
- The FastAPI backend will issue session tokens; the frontend must persist the
  authenticated session (token) across app restarts and avoid UI flicker by
  checking the persisted session before rendering auth-gated screens.
- Implement a single `AuthProvider` at the app root to read the session once
  (from a secure storage adapter such as `expo-secure-store`) and pass the
  session down to child screens.
- Do not duplicate session reads across screens; maintain a single source of
  truth to avoid re-render races.
- Never store or expose backend secret keys in the client. Use secure storage
  for tokens where appropriate.

## Email OTP verification
- OTP input is 6 boxes. Auto-advance focus between boxes as each digit is
  entered; auto-submit once all 6 are filled.
- The email/OTP flows are implemented by the FastAPI backend. The frontend
  should call the backend's auth endpoints (signup, verify, resend) once the
  API is available. For now, the frontend contains TODO(api) placeholders
  where Supabase calls used to be.

## Conventions
- All API calls should go through `/lib/api.ts`.
- Prefer cursor-based pagination for feeds (not offset).
- Server-side policies, migrations, and triggers are the responsibility of the
  backend team and live in the backend repository.
- Don't invent new screens or flows not listed above without flagging it first.
